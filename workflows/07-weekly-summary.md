# 7. Weekly client summary

Use with `PROMPT.md` and the completed brief.

## Inputs

Current and previous comparable campaign exports, conversion definitions, reporting dates, actual change log, and any reviewed outputs from workflows 1–6. Six days is not a full week: name the actual period and any weekday-composition differences. If prior data is absent, deliver a current-period summary without invented comparisons.

## Copy-paste task

Write a concise client-ready **draft** using `templates/weekly-report.md`. Start with the result, then show the supporting metrics and caveats. Recompute aggregate CTR/CPC/CPA from totals. Compare equivalent conversion definitions and period coverage. Label conversion-lag effects and unqualified lead counts.

Separate four sections: observed results, changes actually made, proposed next steps, and client decisions needed. Only the change log can establish a completed change; recommendations from this session remain proposals. A log entry establishes timing, not causality. Do not turn correlation into a claim that a copy edit caused an uplift.

Include spend, clicks, conversions, CPA, and value/ROAS only when meaningful and supported. Show comparison deltas and the underlying dates. Avoid vanity metrics and unsupported “waste saved” totals. If tracking or data quality blocks interpretation, put that first rather than burying it.

End with at most three actions, each with an owner role, evidence, approval status, and proposed review timing. Do not commit a person to a date they have not agreed to. Add a private analyst appendix with source rows, calculations, coverage gaps, and the fact/proposal distinction.

## Deliverables and review

- `07-weekly-summary.md`: client-ready draft with a separate analyst appendix.
- Updated decision register, preserving actual approval states.

Do not email, message, publish, or upload the report anywhere. Remove unnecessary client identifiers and verify every number before sharing it yourself.
